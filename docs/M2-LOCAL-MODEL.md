# M2 production artifacts and verification boundaries

This is a static-assets-only configuration: `glossquote-print-size`, `printsize.glossquote.com`, compatibility date `2026-10-18`, assets `./dist-production`, HTML handling `none`, custom 404, no Worker script or binding. `workers_dev`, preview URLs, CLI metrics, observability, logs and traces are explicitly disabled under the product's privacy contract. No Cloudflare CLI/API deployment or account access is part of this toolchain.

Production generation reads the fixed M1 public assets, changes only the two page heads for canonical/alternate/OG/WebApplication metadata, replaces robots, and adds sitemap plus `_headers`. Page bodies, core JavaScript, UI JavaScript, CSS and the 404 page must remain byte-identical. `release/m1-preview-manifest.json` locks the approved seven preview assets. The production manifest is outside `dist-production` so it cannot be uploaded as a client asset.

The local model on `127.0.0.1:5211` serves exact static asset paths and a custom 404 for unknown paths, including directory aliases. It does not apply an SPA fallback. Query strings do not change the static asset selected. `_headers`, build manifests, source files and configuration are not HTTP assets. GET/HEAD are supported; other methods receive the local model's deterministic 405. This finite model is not a full Cloudflare emulator and does not verify CDN defaults, bot settings, live routing, RUM, DNS or actual deployed responses.

The `_headers` model implements the emitted exact/one-splat path subset, case-insensitive header names, matching-rule inheritance, comma joining, and `! Header-Name` detachment. Canonical pages detach inherited `X-Robots-Tag` and CSP before setting `index, follow` and their single exact JSON-LD hash. Noncanonical paths and 404 retain noindex. The robots model applies longest matching prefix/exact rules, with Allow winning equal specificity; tests apply these rules to every needed HTML/JS/CSS asset, not just text patterns.

References reviewed on 2026-10-18: [Cloudflare custom headers](https://developers.cloudflare.com/workers/static-assets/headers/), [HTML handling](https://developers.cloudflare.com/workers/static-assets/routing/advanced/html-handling/), [Wrangler configuration](https://developers.cloudflare.com/workers/wrangler/configuration/). The local tests cover the subset used here. Actual production responses remain a later release gate.

M1's real bilingual checks, exact C09/C10 threshold behavior and 320px page keyboard evidence are historical completed checks. Its manual capability gaps remain: real JS-disabled/fault browser, native 200% zoom, physical mobile keyboard/occlusion, offline/cold offline, complete Network/Storage/cache/cookie observation, confirmed persisted BFCache and screen-reader speech. Actual printing/quality and excluded native clipboard/download/file picker workflows are not proved by math or mocks.

After a user focus/IME incident, all further browser/native/computer UI work, including hidden-tab navigation/fill/click/press/resize/screenshot, was stopped. M2 browser checks are `NOT_RUN_USER_FOCUS_INCIDENT` until the primary proves an isolation mechanism and explicitly reauthorizes UI work. Background CLI tests/builds and loopback HTTP probes continue. Permission to continue background work does not restore hidden IAB input. Hidden tabs are not claimed to be free of focus effects. No new UI call was made for diagnosis, no workaround UI technology was tried, and no software was installed for this purpose.
